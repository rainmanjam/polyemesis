## Verified clean

Opus checked and cleared, with specific line references:

- **Mutex discipline.** Every read and write of `measured`, `probed`, `measuredMode`, `source`, `videoInfo` is under `e.mu`. The bugs above are logical races across dropped locks, not memory races — which is why `-race` passes.
- **Lock ordering** across `manager.mu` / `rtmpserver.mu` / `engine.mu`: sequential, never nested. No deadlock.
- **No subscribe/publish deadlock** from tightening `Ready` — `serveSubscriber` checks only key validity, never `Ready`, so the ingest child can always attach and bootstrap the condition its own publisher depends on.
- **Backup addressing** — the backup child dials `token + backupTokenSuffix`, resolving to exactly the `PublisherKey{SourceID, Backup:true}` that `HasSubscriber(s.ID, true)` reads. The SRT-backup path spawns no child but is excluded from registration, so it cannot produce a permanently-false `Ready`.
- **The hold's ordering choices** — planning and stopping while held, skipping only the start, is correct as documented. The failures above come from *when* the empty map is computed, not from passing it.

## Reading of the results

Findings 1, 2 and 3 are all consequences of work done on this branch, and 2 is a
plain regression: destinations that would have published the slate on a cold
start now stay down. Finding 6 is the same mistake in a place the fix never
reached.

The pattern across the whole session holds here too — the defects are not in the
routing or the transport handling, they are in *when* state is read relative to
when it changes.
